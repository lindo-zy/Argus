# Argus 前端演示

当前设计基线：2026-11-01。项目总览见[根说明](../README.md)，页面规范见[交互规范](../docs/08-页面与交互规范.md)，数据方案见[数据表与 Redis](../docs/07-数据表与Redis.md)。

Vue 3 单页应用，按已确认的深浅色 UI 方案实现。当前无后端代码，不需要数据库或任何外部服务账号。

## 启动

使用 Node.js `^22.18.0 || >=24.12.0`，在本目录执行：

```sh
npm ci
npm run dev
```

打开终端输出的本地地址，默认 `http://127.0.0.1:5173`。端口冲突时可运行 `npm run dev -- --port 5174`。

```sh
npm test          # 使用 Node 自带测试运行器验证 mock 状态约束
npm run build    # 生成 dist/ 静态资源
npm run preview  # 本地检查构建结果
```

`dist/` 可以交给普通静态文件服务器托管。页面使用 hash 导航，无需后端路由回退规则。

## 当前功能

- 环境资源中心：状态、架构、类型和关键字筛选，卡片/列表切换，分页，环境详情及关联设备。
- 版本总览：版本/周期筛选、SVG 图表、版本链路、当前资源快照、执行与待办入口。
- 借用：空闲环境直接借用，无需审批。一次多选环境后逐项检查，可借的直接成功，不可借的跳过并返回具体原因；只对成功环境建立借用单。
- 自助资源池：用户直接新增、编辑和移出环境/设备，调整设备关联，无需管理员介入；保留历史记录并防止在占用期间修改资源配置。
- 设备资产与维护：唯一设备及关联环境查询、用户自助创建维护、复核恢复或隔离。
- 人员管理与权限：管理员新增人员、调整角色、停用/启用，并可切换演示身份；人员管理入口仅管理员可见，普通人员直接访问时重定向回环境资源。权限模型从简：管理员拥有全部权限；普通人员仅删除类危险操作（移出环境/设备、重置演示数据）与人员管理修改受限，其余操作全部放行。守卫规则：不能修改当前身份自己，始终保留至少一名启用管理员。UI 禁用与 mock API 校验双层兜底；旧版本地数据自动迁移出人员清单。
- 流水线配置与执行记录：只读 XML 样例、已发布配置启动演示任务、执行终态、对账、清理和释放。
- 质量分析：历史趋势与问题详情示例。
- 外观：浅色、深色、跟随系统，浏览器持久化；大屏模式临时使用深色，退出恢复原偏好。
- 全局搜索、通知待办、空态、操作错误提示、加载态、键盘焦点、原生 dialog 焦点约束和移动端布局。

## 依赖

生产依赖只有 `vue`。开发依赖只有 `vite` 和 `@vitejs/plugin-vue`。未使用 UI 组件库、图表库、图标库、路由库、状态库、HTTP 库、外部字体或 CDN。

图标和图表直接使用 SVG；导航使用 hash；共享状态使用 Vue 的响应式能力。

## Mock 与真实接入边界

所有 mock 函数在浏览器里执行，并模拟异步延迟。数据保存到本域的 `localStorage`：`argus.mock.v1`；主题键为 `argus.theme`。存储不可用时降级为内存数据。可在「工作空间设置」中恢复演示样本。

当前资源状态随操作变化；版本总览历史数据为固定截至 **2026-10-30** 的 fixture。通过率、执行次数和失败原因会响应版本/周期筛选；利用率、准备耗时、证据完整率使用清楚标注的 7 天固定样本，问题数量使用版本快照。版本链路是目标接入示意。近期执行与问题只展示部分示例明细，不能据此断言真实系统已接入或已有实际收益。

环境借用明确不设审批，空闲资源直接建立演示租约；设备到期不会自动释放。共享设备互斥、待对账、清理和健康复核都在 mock 层体现。但浏览器存储**不提供跨标签页或跨用户的事务互斥、身份验证或授权保障**，此原型不能直接作为生产环境管理系统使用。

一次申请可包含多个环境：`borrow({ envIds: ['ENV-ARM-01', 'ENV-X86-02'], hours: 4, purpose: '联合验证' })`。返回 `{ lease, requestedEnvIds, outcomes }`：`outcomes` 逐项记录 `envId`、名称、`borrowed/skipped`、原因码和原因文字；`lease` 只包含成功环境及去重的设备快照，全部不可借时为 `null`。占用、维护、隔离、移出资源池和不存在只影响对应项，其他空闲环境照常成功。同批共享设备只占用一次，对其他借用和任务保持独占。用途、时长或请求结构非法仍属于整次请求错误。

成功环境按一张借用单统一续期、归还及健康复核；未成功环境不进入借用单，不会锁定其独有设备。健康复核由用户自助操作，属于资源检查，不是管理员审批。原有 `envId` 单环境请求和已保存记录仍可继续读取操作，无需重置数据。

环境与设备通过 `saveEnvironment`、`saveDevice` 自助新增/编辑，通过 `archiveEnvironment`、`retireDevice` 移出资源池。移出保留历史数据。使用中、维护中、待复核/清理/对账的资源不能改动配置或移出；设备仍被有效环境引用时，先由用户编辑关联或移出环境。修改资产元数据不会把隔离或占用状态改为空闲。

不维护独立 `os_versions` 表，系统版本为可选文本及执行快照；页面版本选项目前是固定样本。Redis 仅为后续可选缓存，不替代持久租约、设备占用与历史记录。

后续关系模型使用 `leases`、`lease_environments`、`lease_resources` 表达实际借用及设备快照，不需要借用审批表或管理员处理节点。批量接口按环境隔离失败，每个环境内部的所有设备获取必须完整成功，批次整体允许部分成功；普通用户可直接维护资源池。操作历史可统一记入资源事件表。本轮未新增后端、Redis 或数据库代码。

后续接入时可保持页面组件，替换 `mock/api.js` 的异步服务实现为 HTTP 适配器，并对齐 [接口与数据契约](../docs/03-接口与数据契约.md)；真实身份、设备锁、事务、审计和执行协调由后端保证；环境借用及资源池维护不引入管理员审批。本次没有实现任何后端服务，也未连接 Gerrit、Jenkins、JFrog、RDC 或测试设备。

## 手工验收建议

1. 进入环境页，筛选架构，切换列表视图和主题；确认筛选条件保留。
2. 一次选择空闲环境和执行中环境，提交后应分别显示成功和跳过；借用单只包含成功环境，刷新后仍保持。再选择全部不可借项，确认不建单，并从结果页调整失败项重试。
3. 提交整单归还，确认所有所选环境仍不可借；模拟复核通过后一起恢复可用，异常时整单隔离。
4. 复核存储维护环境，申请网络环境；确认共用设备导致存储环境同步锁定。
5. 打开待对账任务，模拟终态后确认仍待清理，清理通过才释放。
6. 在版本总览切换版本和时间，打开指标口径，进入大屏再退出，检查个人主题恢复。
7. 自助新增设备，返回环境草稿保存，编辑和移出；确认占用资源不能修改配置，移出不删历史。
8. 用手机宽度检查菜单、筛选、详情和表格横向滚动；按 Escape 关闭弹窗，Tab 应保持在原生对话框内。
